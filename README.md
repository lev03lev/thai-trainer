# תרגול תפריט — המחתרת התאילנדית

מערכת תרגול לקראת מבחן התפריט, בעברית ו-RTL, לטלפון ולמחשב. כל התוכן מבוסס **רק** על חוברת הלימוד (39 עמודים), וכל תשובה מפנה לעמוד המקור.

## מה יש במערכת

- **מצבי לימוד:** תרגול יומי קצר · תרגול חופשי · זיהוי לפי תמונה · מנה אחת לעומק · שאלות הפוכות והשוואות · תרחישי אורח (כולל סימולציית הזמנה) · מבחן מדמה (25 שאלות, 15 דקות) · חזרה על טעויות · תרגול ממוקד לאלרגיות וגלוטן.
- **חלוקת שאלות הבסיס:** 30% תיאור ומרכיבים, 30% משפט מלצרית, ו-40% בחלוקה שווה בין שאר התחומים המאומתים. טעות בשאלת בטיחות מקבלת אזהרה וחוזרת בתרגול ממוקד **מעבר** לחלוקה הזו.
- **משוב מיידי** עם הסבר ותגית מקור (עמוד + מודפס / כתב יד).
- **עמוד ״בדיקת תוכן״** (`/review`): טבלת סקירה של כל המנות והמאפיינים, ורשימת השאלות הפתוחות עם צילום מהסריקה.
- **מעקב התקדמות** לפי תחום ולפי מנה, רצף ימים ותוצאות מבחנים.
- **סנכרון בין מכשירים** בקוד סנכרון (ללא חשבון).

## אמינות המידע — איך זה בנוי

- `src/data/menu-spec.ts` — תעתיק מובנה של החוברת. לכל מנה: שם, תיאור, מרכיבים, משפט מלצרים, אלרגנים, גלוטן, חלב, MSG, חריפות, טעמים חזקים, שינויים אפשריים ושאינם אפשריים, הערות, גרסאות וכתב יד.
- כל עובדה נשמרת עם **עמוד, סוג מקור (מודפס / כתב יד) ונוסח המקור** (`src/data/menu.ts`).
- **שדה ריק = לא ידוע**, ולא ״אין״. בשאלות התשובה הנכונה במקרה כזה היא ״לא מצוין — לבדוק מול המטבח״.
- **גרסאות נשמרות בנפרד** (למשל: ״גרסה טבעונית — מכילה גלוטן״). התאמה של גרסה לא הופכת את הגרסה הרגילה למתאימה.
- עובדה לא ודאית מסומנת `block` ומפנה לשאלה ב-`src/data/issues.ts`. **היא חסומה**: לא מופיעה בשאלות, בתשובות או בתרחישים.
- המנה הנוספת בכתב יד בעמוד ״קריספי רייס״ הושמטה לפי ההנחיה. מנת הקריספי רייס המודפסת נכללה.
- התמונות הן האיורים שמודפסים בעמוד של כל מנה בחוברת (`public/dishes/pNN.jpg`, לפי מספר העמוד).

### עדכון התוכן אחרי הכרעה בשאלה פתוחה

1. מעדכנים את המנה ב-`src/data/menu-spec.ts` (מסירים את ה-`block` או מתקנים את הערך).
2. מעדכנים או מוחקים את השאלה ב-`src/data/issues.ts`.
3. מריצים `npm test`. הבדיקות מוודאות שכל תשובה היא ציטוט מהחוברת ושאין דליפה של תוכן חסום.

אין עריכת תוכן מהדפדפן. התוכן משתנה רק דרך הקוד (ובגיט).

## התאמה אישית (`/personalize`)

- **20 ערכות עיצוב** (11 בהירות, 9 כהות) + ״לפי המכשיר״: קלאסי, שקיעה, מנגו סטיקי רייס, סאקורה, לבנדר, ארקטי, אוקיינוס, יער, מדבר, רטרו, לוטוס, לילה חם, חצות, גלקסיה, ניאון, סייבר, בנגקוק בלילה, אמרלד, זהב תאילנדי, ניגודיות גבוהה.
  - כל ערכה מוגדרת פעם אחת ב-`src/themes/themes.ts`: **צבעים** (`tokens`) ו**אופי** (`style`): רקע מצויר (כוכבים, רשת, נקודות, דיונות...), גרדיאנט לכפתור, גופן לטקסט ולכותרות, עיגול פינות, עובי מסגרת, צל, וכותרות בצבע הערכה. ה-CSS של כל הערכות נוצר מהקובץ.
  - **להוספת ערכה מוסיפים אובייקט אחד.** `tests/themes.test.ts` בודק לה ניגודיות WCAG (כולל טקסט על שני קצוות הגרדיאנט של הכפתור), ונכשל אם מופיע צבע קבוע בקוד הממשק.
  - מעבר בין ערכות: מעגל שמתפשט מנקודת הלחיצה (View Transitions; בלי תמיכה או עם ״פחות תנועה״ — החלפה מיידית). ריחוף על ערכה מציג אותה בכרטיס הפרופיל לפני הבחירה. סקריפט ב-`<head>` מונע הבהוב בטעינה.
- **אווטרים:** יותר מ-90 מוכנים בשש קטגוריות, ו**עורך אווטר** (פנים, צבע עור, עיניים, גבות, פה, תסרוקת/כיסוי ראש וצבע, זקן/שפם וצבע, משקפיים וצבע, בגד, צבע והדפס, רקע — כולל גרדיאנטים), עם אקראי, ביטול פעולה ואיפוס. דמות מהגלריה אפשר לפתוח בעורך ולהמשיך לעצב.
  - איורים שלנו: `src/avatars/avatars.tsx`. ספריית [DiceBear](https://www.dicebear.com) (MIT) עם סגנונות שאינם דורשים ייחוס: avataaars ו-bottts (Pablo Stanley — Free for personal and commercial use), lorelei, notionists ו-pixelArt (CC0). הציור נעשה בדפדפן, בלי רשת, והמודול נטען רק כשצריך.
  - **חלקי העורך מוגדרים כנתונים** (`PART_GROUPS` ב-`src/avatars/dicebear.ts`); אפשרויות חדשות בספרייה נכנסות אוטומטית. גלריה: `src/avatars/catalog.ts`.
- **אחסון:** `localStorage`, דרך הממשק `PreferencesRepository` (`src/lib/preferences/repository.ts`). המבנה (`model.ts`: ערכה, שם, מזהה אווטר והגדרת העורך) הוא JSON פשוט שמתאים להעברה ל-user settings בשרת — כותבים מימוש נוסף לממשק, בלי לשנות את המסכים.

## הפעלה מקומית

דרוש Node.js 20 ומעלה.

```bash
npm install
npm run dev          # http://localhost:3000
```

בלי משתני סביבה, ההתקדמות נשמרת רק בדפדפן, ועמוד ״סנכרון״ מציג שהשירות לא הוגדר.

## בדיקות

```bash
npm test             # בדיקות נתונים ומנוע שאלות (vitest)
npm run build && npm start -- -p 3100
npm run test:e2e     # בדיקות דפדפן בטלפון ובמחשב (Playwright; התקנה חד-פעמית: npx playwright install chromium)
```

בדיקת הסנכרון בדפדפן דורשת שרת Redis. לבדיקה מקומית יש שרת דמה:

```bash
node e2e/mock-redis.mjs &
KV_REST_API_URL=http://127.0.0.1:3199 KV_REST_API_TOKEN=test-token npm start -- -p 3100
```

## פריסה ב-Vercel

1. מעלים את הריפו ל-GitHub ומייבאים אותו ב-Vercel (Framework: Next.js, בלי הגדרות מיוחדות).
2. **סנכרון בין מכשירים (אופציונלי):** בפרויקט ב-Vercel ← Storage ← Create ← **Upstash for Redis** (בחינם עד מכסה נדיבה; דורש חשבון Upstash שנוצר דרך Vercel). אחרי החיבור נוספים אוטומטית `KV_REST_API_URL` ו-`KV_REST_API_TOKEN`. עושים Redeploy.
3. בלי שלב 2 הכול עובד, אבל ההתקדמות לא עוברת בין מכשירים.
